There is no contact form, dark mode, blog, analytics script, or client-side animation runtime. Those are deliberate scope decisions, not unfinished pages.

### Visual proof

The site uses code-generated **system maps** instead of screenshots. The maps are rendered from `src/content/architecture.ts`, the same registry the case-study architecture section reads. They are diagrams of documented architecture, not mock interfaces, and the case pages say so in the figure caption. No stock photo, fake dashboard, invented metric, or client screenshot appears anywhere.

### Content model

Each case study is a validated MDX file:

- `src/content/work/*.mdx` — body + frontmatter.
- `src/lib/content/schema.ts` — zod contracts for title, tagline, contract, capabilities, stack, links, metrics, evidence, SEO.
- `src/lib/content/load.ts` — reads, validates, sorts, resolves previous/next.
- `src/lib/content/mdx-components.tsx` — maps `Claim` and `Architecture` into MDX.
- `src/components/evidence/claim.tsx` — claim, inline marker, evidence margin.
- `src/components/work/architecture-view.tsx` — stage cards + text flow + boundary note.

Build fails if a slug mismatches its filename, a frontmatter field is missing, a metric is malformed, or fewer than two evidence notes exist. That is intentional: content that cannot meet the contract does not ship.

**MDX constraint:** `next-mdx-remote`'s RSC mode strips JSX expression attributes for safety. Props must be string literals in MDX (`n="1"`, not `n={1}`). `Claim` also derives the number from the `id` as a fallback. This is a library security behaviour, not a bug in the site.

**Tables:** `remark-gfm` parses the Markdown tables in all four case files. Each table is wrapped in a keyboard-focusable `.prose-table-wrap` scroll container; at 320px the table type scales down so the three-column failure tables fit without page overflow.

### Design and motion

- Warm paper, blue-black ink, one vermillion signal; OKLCH tokens in `src/app/globals.css`.
- Bricolage Grotesque (display), Instrument Sans (body), JetBrains Mono (labels), Instrument Serif Italic (accent).
- 1px rules, 2px geometry, no shadows, no glass, no glow.
- Motion is CSS only: hero rise, mobile sheet, scroll-driven figure reveal behind `@supports (animation-timeline: view())`, all behind `prefers-reduced-motion` guards.
- Print stylesheet hides navigation, collapses the article grid, removes hash-link artefacts, and keeps case files readable on paper.

### Security

`next.config.ts` sends these headers on every route:

- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Frame-Options: DENY`
- `Permissions-Policy: camera=(), microphone=(), geolocation=(), browsing-topics=()`
- `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
- `Content-Security-Policy` with `default-src 'self'`, self-hosted fonts and images, `frame-ancestors 'none'`, and `object-src 'none'`

The CSP is enforced. `script-src` and `style-src` include `'unsafe-inline'` because Next injects the inline bootstrap script and the site uses inline styles; there is no `'unsafe-eval'` and no third-party origin. A nonce or hash-based policy would require dynamic rendering or build-time hashes and remains future work. The earlier report-only header was removed after WebKit correctly warned that a policy without a reporting endpoint has no effect. There is no form backend, no analytics, and no cookie at launch.

### SEO and sharing

- Per-page title, description, canonical URL, Open Graph, and Twitter metadata.
- Person, CreativeWork, BreadcrumbList, and ItemList JSON-LD.
- A 1200×630 brand OG card at `public/og.png`, referenced by default on every page.
- Per-case OG cards are **not** generated yet. `seo.ogAlt` remains reserved for that work.

### Accessibility audit

On 28 Oct 2026, axe-core 4.14.0 was injected into Playwright Chromium 1248 and run against `/`, `/work`, all four case files, `/about`, and a 404 at 320×800, 390×844, and 1440×1000. The mobile menu was audited open at both narrow widths. Result: **0 violations** for WCAG 2.0/2.1/2.2 A and AA tags.

The first run found five violations, all fixed before the clean run:

1. The home link's accessible name did not include the visible mobile wordmark.
2. Project cards had a short `aria-label` that excluded most of the visible card text.
3. Archive rows had the same compressed-label problem.
4. The French ATS link said “French CV” but its visible text was “Français”.
5. The skip link sat outside every landmark; it now has a labelled navigation wrapper.

A separate 320px sweep found the contact email forcing a 25px horizontal overflow. The email now scales down at narrow widths, allows breaking under text-spacing overrides, and both contact columns allow shrinking. The audit is repeatable with `npm run audit:a11y` after `npm run build && npm start`. Install the browser once with `npx playwright install chromium`.

### Reflow, text spacing, and motion

- **200% zoom equivalent:** a 1280px desktop laid out at a 640px viewport. All 8 routes pass with no horizontal page overflow.
- **WCAG 1.4.12 text spacing:** line-height 1.5, letter-spacing 0.12em, word-spacing 0.16em, paragraph spacing 2em. All 8 routes pass at 1440px and 390px. The email link breaks rather than forcing the page wider; data tables scroll inside their wrapper, which WCAG permits for two-dimensional content.
- **Reduced motion:** with `prefers-reduced-motion: reduce`, `document.getAnimations()` returns no running animations and `scroll-behavior` is `auto` on `/` and the flagship.
- **Tables at 320px:** `remark-gfm` now parses the Markdown tables. Before the fix they rendered as literal pipe text and overflowed in Firefox. All four case tables fit at 320px; a focusable scroll wrapper remains for text-spacing overrides.

### No JavaScript

The site is server-rendered, so content and links exist before hydration. Two controls needed a fallback:

- **Home Index:** the interactive tablist/accordion is paired with a stacked list of the same four projects. `@media (scripting: none)` hides the island and shows the stack; each item keeps its title, descriptor, outcome, stack tags, and case link.
- **Header at narrow widths:** the menu trigger is a client island. When scripting is off, the trigger is hidden and a four-link nav row (Work, About, Contact, Resume) is shown. At 768px and above the normal desktop nav is used.

`npm run audit:nojs` drives Playwright with JS on and off at 390×844 and 1440×1000 across 8 routes, 32 checks total. With JS off, `/` kept 7,425 characters of content and 30 links, four stacked Index items, and four header links at 390px, with no overflow. With JS on, the fallbacks were hidden and the interactive Index and menu were visible. `/work`, all four case files, `/about`, and the 404 also render without JS. Forcing the fallback visible and the interactive Index hidden produced 0 axe-core 4.14.0 violations at 390 and 1440.

### HTML validity

Nu HTML Checker 26.10.12 validates the served HTML for all 8 routes. Result: 0 errors and 0 warnings. The 281 remaining messages are `info` notes about React's self-closing void elements (`<meta />`, `<br />`), which HTML5 ignores.

### Cross-browser

Chromium 1248, Firefox 157, and WebKit 27.2 were driven with Playwright at 1440×1000 and 390×844. All 8 routes return the expected status with no page overflow or console errors (the 404 request itself is expected). The mobile menu opens, moves focus inside, closes on Escape, and returns focus to the trigger; the Index responds to ArrowDown in all three engines; the copy-email button reaches its `Copied` state in all three.

WebKit initially failed to launch because the host lacks `libavif16`. The package and its two library dependencies (`libgav1-1`, `libyuv0`) were unpacked into the Playwright WebKit bundle, after which WebKit 27.2 launched and passed. This is an environment workaround on a Linux host; it exercises the WebKit engine, not Safari's UI chrome, and is not a substitute for a real macOS/iOS device pass. The enforced CSP produces no WebKit console warning; the previous report-only header did, which is why it was replaced.

### JavaScript budget

Measured against the served HTML of the production build, summing the gzip size of every script with a `src` and excluding the `noModule` polyfill chunk that modern browsers do not fetch:

| Route                       | Scripts | Gzip     | Brotli   |
| --------------------------- | ------- | -------- | -------- |
| `/`                         | 8       | 144.0 KB | 123.4 KB |
| `/work`                     | 8       | 139.3 KB | 119.4 KB |
| `/work/documents-assistant` | 8       | 140.0 KB | 120.0 KB |
| `/about`                    | 8       | 139.3 KB | 119.4 KB |

The 120 KB gzip budget is **not met**. About 115 KB gzip is React DOM (45.2 KB) plus the App Router/Turbopack runtime (70.1 KB) before any site component; the remaining chunks are shared app code and the small client islands. The four routes differ by less than 5 KB, which confirms that page code is not the driver. Options if the 120 KB target becomes mandatory: a non-hydrated static HTML build, a framework with a smaller client runtime, or dropping client navigation and interactive islands. None of those is worth doing for a portfolio that already scores 96–99 on mobile performance; the miss is recorded rather than hidden.

## 3. Honest boundaries

These are shipped on purpose:

1. **Flagship proof is partial.** Documents Assistant has no public repo, demo, screenshot, or measured retrieval benchmark. The case file claims architecture and behaviour only, and says the evaluation is unrun.
2. **Sadine and RFID are private.** Counts are repository artifacts. No customer, employee, or business data is published.
3. **Anomaly’s MCP path is partial.** The MCP server accepts only the mock scan type; the case file states this.
4. **No screenshot evidence exists for any project.** The diagrams are honest substitutes; they are not proof of a running interface.
5. **The CV is a one-page subset.** It is current as of 27 Oct 2026, but it omits Sadine, RFID, and Anomaly Detection, and it includes the phone number. Re-sync all four PDFs after any fact or metric change.
6. **No analytics.** The footer claims no tracking pixels; keep that true unless the copy changes.
7. **Automated audits are not a certification.** axe-core 4.14.0 reports zero WCAG 2.2 A/AA violations at 320, 390, and 1440px, and the repeatable Lighthouse audit scores 96–99 performance (three-run medians on the final build) and 100 accessibility, best practices, and SEO. Chromium, Firefox, and Playwright WebKit pass scripted cross-browser checks. Screen-reader, real Safari, real-device, and remote CI runs remain. First-load JavaScript is 140–144 KB gzip, above the 120 KB target.
8. **Public evidence is a snapshot.** The public repositories can change after 27 Oct 2026; the ledger records the commit date, not a permanent guarantee.

## 5. Deploy procedure

1. `npm ci`
2. `npm run typecheck`
3. `npm run lint`
4. `npm run format:check`
5. `NEXT_PUBLIC_SITE_URL=https://<final-domain> npm run build`
6. Deploy to Vercel with the same environment variable set for Production and Preview.
7. Verify:
   - `/`, `/work`, all four case files, `/about`, `/resume.pdf`, `/resume-fr.pdf`, `/resume-ats.pdf`, `/resume-fr-ats.pdf`, `/sitemap.xml`, `/robots.txt`.
   - Canonical URLs and OG image resolve against the final domain.
   - 404 returns a 404 status.
   - `npm run audit:links`, `npm run audit:a11y`, and `npm run audit:lighthouse` pass against the deployed origin (`BASE_URL`/`AUDIT_BASE_URL`).
   - Print a case file; header/footer are gone and the evidence notes stay with their claims.
8. Point the domain, then 301 the old `yassine-ben-romdhane.vercel.app` origin. Keep `/resume.pdf` working across the redirect.
9. Submit the sitemap in Search Console after the domain is final.

If `NEXT_PUBLIC_SITE_URL` is unset, the site falls back to the old Vercel URL. That is safe for previews and wrong for a custom domain.

## 6. Maintenance runbook

### Add a case study

1. Copy an existing `.mdx` file and change the slug to match the filename.
2. Fill every frontmatter field; keep `summary` under 340 characters and the 60-second contract short.
3. Add four evidence notes in reading order. Use string props (`n="1"`), never `{1}`.
4. Add an entry to `src/content/architecture.ts` if the system map is new.
5. Add the metrics with a source and a `measuredAt` date.
6. Run `npm run build`; fix schema errors before touching layout.
7. Add every new claim to `docs/evidence-ledger.md` in the same commit.

### Change a claim

1. Verify the source.
2. Update the MDX body, frontmatter claim, and ledger row together.
3. Update `verifiedAt`.
4. If the claim becomes unverifiable, remove it instead of weakening the source.

### Re-verify

Quarterly, and after any project change. Stale evidence is worse than no evidence. If a screenshot, demo, or benchmark lands, upgrade the proof status and remove the corresponding gap from this report.
